# 种子数据（Seed Data）

## 定义

种子数据指应用首次启动时需要预置的基础数据——数据库建好时空空如也，种子数据就像播种一样先把初始内容放进去，之后用户/业务流程产生的才是正式数据。

| | 类比 |
|---|---|
| 数据库 | 一片空地 |
| 种子数据 | 播下去的种子 |
| 业务数据 | 长出来的庄稼 |

## 在本项目中的含义

**种子数据 = `data/profile/resolutions/*.json` 里的真实决议标本**（数据契约、制度化、招聘体系）。

- **为什么需要**：provider 启动时若决议表是空的，`GET /resolutions` 返回空列表——开发和演示都没东西可看。种子逻辑把标本写进数据库，服务一启动就有真实决议可查询。
- **为什么用云端 GitHub 拉取**：`data/profile` 是独立 git 子模块，provider 运行时若直接读本地路径，会依赖子模块是否被 checkout、目录是否完整。改为从云端 GitHub（raw）拉取，服务只要联网就能获取，不依赖本地目录状态。
- **与普通数据的区别**：种子数据是只读初始化的（幂等，重复启动不重复插入），而运行期创建的决议是业务数据。

## 对照示例

```
种子数据（启动时）         业务数据（运行时）
─────────────────        ─────────────────
数据契约决议              用户新建的"本周决议：升级计费方案"
制度化决议                下次周会表决通过的决议
招聘体系决议
```

## 一句话总结

种子数据 = 预置的初始数据，让空系统开箱即有内容。
